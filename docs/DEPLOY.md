# Установка и деплой Home.Media v4

## Требования

- Synology NAS с DSM 7.2+
- Container Manager 2.x (или Docker)
- 2 GB свободной RAM (ядро ~200 MB + postgres ~300 MB + плагины)

## Способ 1: Container Manager (рекомендуется)

1. Скопируйте папку проекта на NAS: `/volume1/docker/hm3-syn/`
2. Container Manager → **Проекты** → **Создать**
3. Укажите путь `/volume1/docker/hm3-syn`
4. Нажмите «Создать» — первая сборка займёт ~10 минут (React + Python)
5. Откройте `http://NAS_IP:8142`

## Способ 2: start.sh

```bash
cd /volume1/docker/hm3-syn
chmod +x start.sh
./start.sh
```

Скрипт сам создаст `.env`, сгенерирует `SECRET_KEY`, соберёт контейнеры
и подождёт готовности ядра.

## Первый запуск

1. Откройте `http://NAS_IP:8142`
2. Создайте аккаунт администратора (пароль минимум 8 символов)
3. Перейдите на страницу **Плагины** → **Установить .hm**
4. Выберите файл плагина — установка и запуск произойдут автоматически

## Полезные команды

```bash
docker compose logs -f home-media      # логи ядра
docker compose down                     # остановить всё
docker compose up -d --build            # пересобрать и запустить
docker compose pull                     # обновить postgres
```

## Обновление ядра

```bash
cd /volume1/docker/hm3-syn
# сохранить бэкап настроек: Настройки → Резервное копирование → Экспорт
git pull   # или скопировать новые файлы поверх
docker compose up -d --build
# импортировать бэкап, если менялся формат конфигов
```

## Резервное копирование

Веб-интерфейс: **Настройки → Резервное копирование**:

- **Экспорт** — скачивает один JSON со всеми настройками плагинов
  (секреты маскируются символами `••••••••`)
- **Импорт** — восстанавливает настройки и перезапускает плагины

Для полного бэкапа скопируйте папку `data/` проекта (там БД и данные плагинов)
+ файл бэкапа настроек.

## FAQ

**Ядро запустилось, но админка пустая.**
Внутри Docker-образа React собирается автоматически (multi-stage:
`admin` → `dist` → `core/app/web/static/admin`), пересоздайте образ:
`docker compose up -d --build`.
При локальном запуске без Docker: `cd admin && npm run build:sync`.

**Плагин в статусе `failed`.**
Откройте страницу «Логи» и посмотрите вывод плагина. Частая причина —
ошибка в `main.py` или недоступный пакет в requirements.txt.
Проверьте `last_error` на карточке плагина.

**Порт плагина занят.**
Ядро само убивает процесс, занимающий назначенный порт, перед запуском плагина.
Если порт держит другой сервис из пула 8100–8200 — переназначьте его,
указав `port_hint` в manifest.
